# 2026-07-06

## SOAR Network-Security Test Case Continuation

This note documents the continuation of the June 30 implementation for the five required network-security test cases in the event-driven SOAR pipeline:

`Ingest -> Normalize -> Trigger YAML Workflow -> Enforce via OpenDaylight`

## Changes Made

### Telemetry Propagation

- Preserved workflow telemetry through `INITIATE_MITIGATION` commands.
- Added telemetry propagation for `INSTALL_PROACTIVE_POLICY` commands in `ModuleRegistryLifecycleManager/src/main/java/com/yourorg/registry/SdkModuleHost.java`.
- This closes the telemetry gap for the ICMP flood test case, because that workflow uses proactive policy installation rather than host-isolation mitigation.

### OpenDaylight Benchmark Logging

- Refactored benchmark logging in `user-defined-modules/src/main/java/com/nis1/thesis/udm/OpenDaylightModule.java` into a shared `logTelemetryBenchmark(...)` helper.
- Benchmark logs now work for:
  - Host isolation / quarantine / IP blocking through `INITIATE_MITIGATION`.
  - Protocol-drop SDN rules through `INSTALL_PROACTIVE_POLICY`.
- The log reports:
  - Suricata alert generation time.
  - System alert receipt time.
  - Workflow execution time.
  - SDN rule application time.
  - Total containment pipeline duration.

### ICMP Flood Workflow

- Updated `WorkflowEngine/workflows/ransomware/suricata_icmp_flood_drop.yml`.
- Added severity propagation into the proactive policy payload:

```yaml
severity: "{{ trigger.payload.severity }}"
```

- This workflow detects `icmp_flood` alerts and installs a protocol-drop policy for ICMP, IP protocol `1`, from the offending source IP.

### Severity Propagation For Mitigation Workflows

The following workflows now propagate severity to the OpenDaylight module:

- `WorkflowEngine/workflows/ransomware/zeek_tcp_syn_scan_isolate.yml`
- `WorkflowEngine/workflows/ransomware/zeek_nmap_recon_contain.yml`
- `WorkflowEngine/workflows/ransomware/suricata_dns_amplification_isolate.yml`
- `WorkflowEngine/workflows/ransomware/suricata_arp_spoof_quarantine.yml`
- `WorkflowEngine/workflows/ransomware/suricata_icmp_flood_drop.yml`

This allows the OpenDaylight module to apply severity-aware handling, especially for reconnaissance.

### Reconnaissance Handling

- Updated `user-defined-modules/src/main/java/com/nis1/thesis/udm/ZeekModule.java`.
- Zeek scan detection now recognizes both:
  - `Scan::Port_Scan`
  - `Scan::Address_Scan`

This supports the Nmap reconnaissance test case, including address scans and ping-sweep style recon.

### ARP Spoofing Inventory Check

- Added `checkConflictingIpMacBindings()` to `user-defined-modules/src/main/java/com/nis1/thesis/udm/services/OpenDaylightClient.java`.
- When ARP spoofing or poisoning mitigation is triggered, `OpenDaylightModule` queries OpenDaylight operational topology and logs conflicting IP-to-MAC bindings.
- The suspected host is then quarantined through the normal OpenDaylight mitigation path.

### OpenDaylight State Restore Access

- Changed `OpenDaylightClient.loadPersistedState()` from package-private to public.
- This matches the existing startup call from `OpenDaylightModule` and fixes a compile-time access error.

## Test Case Matrix

### 1. TCP SYN Scanning

Expected input:

- Event type: `alerts.network.zeek`
- Payload alert type contains: `tcp_syn_scan`
- Severity: `high`

Expected workflow:

- `zeek_tcp_syn_scan_isolate.yml`

Expected response:

- Workflow publishes `INITIATE_MITIGATION`.
- OpenDaylightModule applies host isolation through `ISOLATE_VLAN`.
- Benchmark log appears if telemetry is present.

### 2. DNS Amplification

Expected input:

- Event type: `alerts.network.suricata`
- Payload alert type contains: `dns_amplification`
- Severity is not `low`

Expected workflow:

- `suricata_dns_amplification_isolate.yml`

Expected response:

- Workflow publishes `INITIATE_MITIGATION`.
- OpenDaylightModule applies `ISOLATE_VLAN`.
- Severity is available in additional parameters.
- Benchmark log appears if telemetry is present.

### 3. ICMP Flooding

Expected input:

- Event type: `alerts.network.suricata`
- Payload alert type contains: `icmp_flood`
- Severity is not `low`

Expected workflow:

- `suricata_icmp_flood_drop.yml`

Expected response:

- Workflow publishes `INSTALL_PROACTIVE_POLICY`.
- Payload contains:

```json
{
  "policy_type": "protocol_drop",
  "protocol": "icmp",
  "source_ip": "<offender-ip>"
}
```

- OpenDaylightModule calls `applyProtocolDrop(...)`.
- OpenDaylightClient installs a drop rule for IP protocol `1`.
- Benchmark log appears if telemetry is present.

### 4. ARP Spoofing / Poisoning

Expected input:

- Event type: `alerts.network.suricata`
- Payload alert type contains: `arp_spoofing`
- Severity is not `low`

Expected workflow:

- `suricata_arp_spoof_quarantine.yml`

Expected response:

- Workflow publishes `INITIATE_MITIGATION`.
- OpenDaylightModule checks operational topology for conflicting IP-to-MAC bindings.
- Any conflicts are logged.
- OpenDaylightModule applies `QUARANTINE`.
- Benchmark log appears if telemetry is present.

### 5. Nmap Reconnaissance

Expected input:

- Event type: `alerts.network.zeek`
- Payload alert type contains: `nmap_recon`
- Severity is not `low`

Expected workflow:

- `zeek_nmap_recon_contain.yml`

Expected response:

- Workflow publishes `INITIATE_MITIGATION`.
- OpenDaylightModule checks severity:
  - `critical` or `high`: isolate host with `ISOLATE_VLAN`.
  - other non-low severities: apply targeted `BLOCK_IP`.
- Benchmark log appears if telemetry is present.

## What To Look For In Logs

WorkflowEngine should show:

- Matching workflow name.
- Published command to `workflow_response_queue`.

ModuleRegistryLifecycleManager should show:

- Command consumed from `workflow_response_queue`.
- Dispatch to `INITIATE_MITIGATION` or `INSTALL_PROACTIVE_POLICY`.

OpenDaylightModule should show:

- Received mitigation or proactive policy request.
- OpenDaylight flow installation result.
- For ARP spoofing, conflicting IP-MAC binding checks.
- For telemetry-bearing alerts, a `THESIS PERFORMANCE BENCHMARK` block.
